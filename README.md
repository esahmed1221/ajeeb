# متجر عجيب للأحذية

نسخة جديدة مستوحاة من صور المعاينة التي قدّمها صاحب المتجر. تعمل على خادم VPS باستخدام Node.js 20 أو أحدث، وتدعم PostgreSQL لحفظ الطلبات والمنتجات والإعدادات والموظفين. قاعدة البيانات هي مصدر الحقيقة وتُقرأ عند كل طلب بدل الاحتفاظ بنسخة دائمة من بيانات المتجر في ذاكرة Node. تبقى الصور المرفوعة في مجلد `data/uploads` على السيرفر.

تحتوي النسخة على المنتج `SH 1778` بسعر سابق 240 د.ل وحالي 120 د.ل، بمقاس 41 (قطعتان) ومقاس 43 (قطعة واحدة). صورته الحالية مأخوذة من لقطة شاشة قدّمها صاحب المتجر؛ يُفضّل استبدالها بالصورة الأصلية حين تتوفر.

## ما يعمل الآن

- واجهة عربية متجاوبة، بحث وتصفية حسب المقاس، اختيار المقاس مباشرة من بطاقة المنتج، وصفحة تفاصيل بصور متعددة.
- سلة مع تعديل الكمية أو الحذف، ونموذج طلب بالدفع عند الاستلام.
- حساب التوصيل حسب المدينة، صفحة تأكيد مستقلة، ومنع الطلب إذا لم تتوفر الكمية.
- لوحة إدارة محمية بكلمة مرور مستقلة لإضافة وتعديل المنتجات والصور والمقاسات، متابعة الطلبات، تغيير حالتها، وإرجاع المخزون للطلبات الملغاة والراجعة.
- رقم خدمة العملاء وسياسات الاستبدال والخصوصية من لوحة الإدارة.

## قبل إتاحة المتجر للزبائن

1. استبدل `public/logo.png` بملف الشعار الأصلي عالي الجودة إن توفر. الموجود الآن مأخوذ من صورة أرسلها صاحب المتجر.
2. جهّز كلمة مرور إدارة مختلفة عن كلمة مرور السيرفر، وسر جلسات عشوائيًا طويلًا. لا تُدخل هذه القيم في ملفات المشروع أو المحادثة.
3. أضف بقية المنتجات الحقيقية وصورها وأسعارها ومقاساتها وكمياتها من `/admin`.
4. أضف المدن وأسعار التوصيل، رقم خدمة العملاء، وسياسات الاستبدال والخصوصية.
5. جرّب طلبًا كاملًا من الهاتف على نسخة تجريبية منفصلة وتأكد من ظهوره في لوحة الإدارة. ابدأ النشر ببيانات متجر نظيفة.
6. جهّز نسخًا احتياطية منتظمة خارج السيرفر لقاعدة PostgreSQL ولمجلد `data/uploads`.
7. فعّل HTTPS على `ajeeb.ly` و`www.ajeeb.ly` قبل استخدام لوحة الإدارة أو استقبال بيانات الزبائن.

## التشغيل المحلي

ثبّت الحزم أولًا باستخدام `npm install` (أو `pnpm install`)، ثم عيّن متغيرات البيئة `ADMIN_PASSWORD` و`SESSION_SECRET` و`SITE_ORIGIN` و`PORT` وشغّل `npm start`. لا يُفعّل دخول الإدارة إلا إذا كانت كلمة المرور 16 حرفًا على الأقل وسر الجلسات 48 حرفًا على الأقل. ملف `.env.example` يوضح الأسماء فقط، ولا يحتوي أسرارًا صالحة. التطبيق لا يقرأ ملف `.env` بنفسه؛ حمّل القيم عن طريق systemd أو منصة الاستضافة.

## التشغيل الكامل باستخدام Docker

يتضمن `compose.yaml` التطبيق، وخادم PostgreSQL 18، وخدمة ترحيل مؤقتة. عند أول تشغيل تنسخ خدمة الترحيل بيانات PGlite المحلية، إن وجدت، من `data/postgres` إلى PostgreSQL داخل volume دائم، ثم يبدأ التطبيق. الترحيل آمن لإعادة التشغيل: يسجل اكتماله ولا يكرر البيانات. في النسخة المستنسخة حديثًا يبدأ المتجر بقاعدة PostgreSQL ومجلد صور فارغين داخل Docker volumes.

المتطلبات هي Docker Engine مع Docker Compose v2، أو Docker Desktop على Windows. على جهاز جديد استنسخ المستودع أولًا:

```powershell
git clone https://github.com/esahmed1221/ajeeb.git
Set-Location ajeeb
```

قبل أول ترحيل أوقف أي نسخة محلية من التطبيق حتى لا تتغير قاعدة PGlite أثناء أخذ اللقطة، ثم نفّذ من مجلد المشروع:

```powershell
Copy-Item .env.example .env
```

افتح `.env` واستبدل القيم الثلاث التي تبدأ بـ `replace-with`: كلمة مرور الإدارة، سر الجلسة، وكلمة مرور PostgreSQL. يمكن توليد قيمة عشوائية سداسية عشرية في PowerShell وتشغيل الأمر مرة مستقلة لكل قيمة:

عند نقل تثبيت قديم يستخدم `ADMIN_PASSWORD_B64` يمكن نسخ القيمة المشفرة إلى `.env` بدل `ADMIN_PASSWORD`، وسيحتفظ المتجر بنفس كلمة مرور الإدارة دون تخزينها كنص صريح.

```powershell
[Convert]::ToHexString([Security.Cryptography.RandomNumberGenerator]::GetBytes(48)).ToLower()
```

بعدها ابنِ وشغّل المجموعة:

```powershell
docker compose up -d --build
docker compose ps -a
docker compose logs migrate
docker compose exec app npm run db:check
```

ينبغي أن تنتهي خدمة `migrate` بالحالة `Exited (0)`، وتصبح خدمتا `database` و`app` بحالة healthy. افتح `http://localhost:3000`، أو العنوان المطابق لـ `SITE_ORIGIN`. قاعدة البيانات لا تُنشر على منفذ المضيف، والتطبيق يستمع افتراضيًا على `127.0.0.1:3000` ليعمل خلف Nginx. غيّر `BIND_ADDRESS` إلى `0.0.0.0` فقط إذا أردت الوصول مباشرةً من أجهزة أخرى.

ملفات `.env` وقاعدة البيانات والنسخ الاحتياطية والصور المرفوعة في `data/` لا تُرفع إلى GitHub لأنها قد تحتوي أسرارًا وبيانات زبائن. إذا أردت نقل بيانات المتجر الحالية إلى الجهاز الآخر، انقل نسخة احتياطية مشفّرة خارج GitHub واستعدها هناك.

أوامر الإدارة اليومية:

```powershell
docker compose logs -f app
docker compose restart app
docker compose down
docker compose up -d
```

الأمر `docker compose down` يوقف ويحذف الحاويات والشبكة فقط، بينما تبقى قاعدة البيانات والصور في الـ volumes. لا تستخدم `docker compose down -v` إلا إذا كنت تقصد حذف قاعدة Docker والصور المرفوعة نهائيًا. مجلد `data/postgres` الأصلي يبقى دون تعديل ويمكن الاحتفاظ به كنسخة رجوع بعد التأكد من نجاح الترحيل.

لأخذ نسخة SQL من PostgreSQL داخل Docker:

```powershell
New-Item -ItemType Directory -Force docker-backups
docker compose exec -T database pg_dump -U ajeeb -d ajeeb --format=plain > docker-backups/ajeeb.sql
```

إذا غيّرت `POSTGRES_USER` أو `POSTGRES_DB` في `.env` فاستعمل القيم الجديدة في أمر النسخ. انسخ أيضًا الصور من volume بشكل دوري، واحتفظ بالنسخ خارج نفس الخادم.

## قاعدة البيانات PostgreSQL

1. محليًا لا تحتاج إلى تثبيت خدمة: إذا لم تضبط `DATABASE_URL` يستخدم التطبيق محرك PGlite (PostgreSQL مضمّن) ويحفظ القاعدة في `data/postgres`. البيانات موزعة على جداول مستقلة للمنتجات والمخزون والزبائن والطلبات وعناصر الطلبات والموظفين والإعدادات. عند نجاح طلب جديد يُنشأ سجل الزبون أو تُحدّث بياناته حسب رقم الهاتف، ويرتبط الطلب به عبر `customer_id` مع الاحتفاظ بنسخة بيانات الزبون داخل الطلب كسجل تاريخي.
2. للإنتاج، أنشئ قاعدة PostgreSQL ومستخدمًا بصلاحيات محدودة ثم اضبط رابطًا مثل `DATABASE_URL=postgresql://ajeeb:password@127.0.0.1:5432/ajeeb`، أو متغيرات `PGHOST` و`PGPORT` و`PGDATABASE` و`PGUSER` و`PGPASSWORD` كما يفعل إعداد Docker.
3. إذا كانت الخدمة المُدارة تشترط TLS، اضبط `DATABASE_SSL=require`. اترك التحقق من الشهادة مفعّلًا إلا إذا طلب مزوّد الخدمة خلاف ذلك صراحةً.
4. عند أول تشغيل ينشئ التطبيق الجداول والفهارس تلقائيًا. إذا وجد التخزين القديم في جدول `app_state` أو ملف `data/store.json`، يستورد محتواه تلقائيًا مرة واحدة دون حذف المصدر القديم.
5. إنشاء الطلب وخصم المخزون يحدثان داخل معاملة واحدة؛ إذا لم تتوفر الكمية تُلغى العملية كاملة ولا يُنشأ طلب ناقص.

## النسخ الاحتياطي المحلي

أوقف التطبيق ثم شغّل `npm run backup` أو `pnpm backup`. ينشئ الأمر نسخة مضغوطة متسقة من القاعدة ونسخة من الصور داخل `data/backups/<date>`. لفحص الجداول بعد إيقاف التطبيق استخدم `npm run db:check`. عند استخدام PostgreSQL خارجية استعمل `pg_dump` بدل أمر النسخ المحلي، واستمر في نسخ `data/uploads` أيضًا.

خذ نسخة احتياطية من PostgreSQL باستخدام `pg_dump`، واحتفظ أيضًا بنسخة من `data/uploads`. جرّب الاستعادة دوريًا؛ النسخة الاحتياطية غير المختبرة لا تكفي.

استخدم `DEMO_PREVIEW=1` لعرض المنتجات التوضيحية فقط حين لا توجد منتجات حقيقية. لا تضبط هذا المتغير في السيرفر المنشور.

## إضافة منتج جديد

بعد إعداد كلمة مرور الإدارة، افتح `/admin` وسجّل الدخول. اضغط **إضافة منتج**، واكتب الاسم والكود والسعر الحالي والسعر السابق إن وجد. المقاسات 40 إلى 46 تظهر جاهزة: اكتب الكمية عند المقاسات المتوفرة فقط، واترك غير المتوفر فارغًا. ارفع صور المنتج (حتى 6 صور)، ثم اضغط **حفظ المنتج**. ستظهر رسالة واضحة إذا كان الكود مكررًا أو البيانات ناقصة. يمكن تعديل المنتج والمخزون لاحقًا من نفس الصفحة. كلمة مرور لوحة الإدارة منفصلة عن كلمة مرور `root` للسيرفر.

### صور واجهة الموقع

من `/admin` افتح **الإعدادات** ثم **الإعلان العلوي**. ارفع صورة مستطيلة للكمبيوتر، ويمكنك رفع صورة منفصلة للهاتف. يدعم الرفع صيغ الصور الشائعة ويحوّلها تلقائيًا إلى JPG عالي الجودة بحجم مناسب للموقع. عدّل العنوان والوصف ثم اضغط **حفظ الإعدادات**. إذا تُركت صورة الهاتف فارغة تُستعمل الصورة الرئيسية، وإذا لم تُضف إعلانًا يبدأ المتجر بالمنتجات مباشرة.

تُضاف أسعار التوصيل من قسم **التوصيل والتواصل** على شكل صفوف: اسم المدينة وسعر التوصيل. استخدم **إضافة مدينة** لإضافة صف جديد وزر **حذف** لإزالته، ثم احفظ الإعدادات.

### الطلبات والموظفون

- تعرض **نظرة عامة** إجمالي الطلبات، الجديدة، المؤكدة، المسلّمة، ومبيعات الطلبات المسلّمة فقط. قسم **الطلبات** يفلتر بالبحث والحالة والتاريخ، ويعرض عدد الطلبات المطابقة وإجمالي قيمتها.
- يدخل المالك برمز الإدارة الحالي مع ترك اسم المستخدم فارغًا. من قسم **الموظفون** يمكنه إنشاء حسابات بأسماء مستخدمين إنجليزية ورموز مستقلة، وتحديد صلاحيات مشاهدة أو تعديل الطلبات والمنتجات والإعدادات لكل حساب.
- تعديل صلاحيات الموظف أو إيقاف حسابه ينهي جلساته السابقة. إدارة حسابات الموظفين محصورة بالمالك. لا يظهر للموظف أي قسم ليس لديه صلاحية مشاهدته، ويتحقق السيرفر من الصلاحيات في كل طلب.
- رمز الموظف يجب أن يكون 12 حرفًا على الأقل. ترك خانة الرمز فارغة عند تعديل حساب قائم يُبقيه كما هو.

## ملاحظات الاستضافة

- ضع المشروع في مجلد مخصص، وشغّله كمستخدم نظام محدود الصلاحيات مع خدمة systemd تعيد تشغيله عند توقفه.
- اجعل Nginx يستقبل `ajeeb.ly` و`www.ajeeb.ly` ويوجه الطلبات إلى المنفذ المحلي للتطبيق. لا تفتح منفذ التطبيق مباشرةً للجمهور.
- خزّن المتغيرات السرية في ملف خارج مجلد الويب بصلاحيات قراءة محدودة، ولا تضعه داخل الأرشيف أو مستودع عام.
- فعّل شهادة TLS صالحة وتجديدها التلقائي. اختبر الوصول إلى `/admin` وطلبًا كاملًا بعد النشر.
- بيانات المتجر والمخزون والجلسات الوظيفية تُقرأ من PostgreSQL، وإنشاء الطلب وخصم المخزون وإرجاعه تتم داخل معاملات قاعدة البيانات. يمكن تشغيل أكثر من عملية Node لبيانات المتجر، لكن عدّاد الزوار وتحديد المحاولات ما زالا محليين لكل عملية، كما تحتاج الصور المرفوعة إلى قرص مشترك أو تخزين كائنات عند التشغيل على أكثر من خادم.

## معلومات ما زالت مطلوبة

صور ومعلومات المنتجات الحقيقية، أسعار التوصيل، هاتف المتجر، نصا سياسة الاستبدال والخصوصية. ربط Meta Pixel أو تنبيهات البريد يحتاج معرّف البكسل أو إعداد البريد من صاحب المتجر، ولم يُفعّل هنا.
